# 3X-UI KIT Custom

Защищённый первоначальный установщик на базе [3X-UI KIT](https://github.com/itsnotkubrick/3X-UI_KIT).
**Этап 1 (0.1.0)**: диагностировать и обходить ошибку `Download x-ui v3.9.0 failed`,
**не затрагивая уже установленные конфигурации VPN**.

> Важно: `--install` разрешён **только на чистой Ubuntu 24.04 LTS**. Если система
> содержит 3X-UI, KIT или следы частичной установки, скрипт откажется работать.
> Он не удаляет и не обновляет существующую панель. Переустановка на рабочем VPS
> с этим инструментом пока НЕ поддерживается.

## Что есть в этапе 1

- Сохранена исходная функциональность KIT с 11 протоколами: при новой установке
  оригинальные сценарии настройки, меню `kit`, `kit-sub`, Xray и клиентских ссылок
  исполняются из зафиксированного релиза KIT без переработки протоколов.
- Панель **3X-UI v3.9.0** и ядро **Xray v26.6.27** закреплены как связка
  оригинального KIT `v1.2.1`. Список версий присутствует, но обновления на
  `v3.10.x`/`v3.11.0` заблокированы до проверки совместимости.
- Перед запуском выполняется проверка Ubuntu, CPU и отсутствия работающей установки.
- Бинарный релиз скачивается и проверяется по закреплённой SHA256 **до** запуска
  официального установщика. Сначала используются GitHub Releases и GitHub API.
  При 504/415 загрузчик пробует сторонние HTTPS-прокси `ghfast.top` и
  `gh-proxy.com`, но **никогда не принимает архив без совпадения SHA256**.
  Эти прокси можно отключить: `KIT_CUSTOM_DISABLE_MIRRORS=1`.
  Есть режим установки из локального архива.
- Исходники KIT и `install.sh` скачиваются из фиксированных тегов и проверяются
  по Git Blob hash; `install.sh` дополнительно проверяется по SHA256.
- Minimal patch: подтверждённый архив копируется в ожидаемый официальный
  установщиком путь. Проверка SHA256 сохраняется. Никакие протоколы и данные
  пользователей патч не затрагивает.
- Диагностика GitHub / портов / версии ОС без изменения системы.
- Автоматические офлайн-тесты; CI для Ubuntu 24.04.

## Быстрый старт — одна команда

Для **чистой Ubuntu 24.04 LTS**, после переключения репозитория
`Lenin0703/3x-ui-kit-custom` на **Public**, подключитесь к VPS по SSH и запустите:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/Lenin0703/3x-ui-kit-custom/main/bootstrap.sh)
```

Загрузчик скачивает только проверенные SHA256 исходники из этого репозитория,
затем вызывает установщик с `sudo` (или сразу от root) **без ввода кодового слова**.
После этого запускается обычная интерактивная настройка KIT.
**Не используйте `curl ... | bash`**: это передаёт stdin установщика из канала
и мешает интерактивным вопросам. Используйте именно `bash <(curl ...)`.

На сервере, где уже есть 3X-UI или остатки KIT, режим установки **откажется**
что-либо менять. Для проверки без установки:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/Lenin0703/3x-ui-kit-custom/main/bootstrap.sh) --diagnose
```

Если `curl` отсутствует: `sudo apt update && sudo apt install -y curl`.
Скрипт требует также `python3` и `sha256sum` (на обычной Ubuntu 24.04 уже доступны).
Если репозиторий приватный, прямое скачивание из GitHub Raw без авторизации
не работает.

### Запуск из локальной копии

Из распакованной папки:

```bash
bash install.sh --versions
bash install.sh --diagnose
```

Если на VPS уже есть 3X-UI, **на этом остановиться**. Диагностика покажет
обнаруженные пути. Следующий этап реализует проверенное резервное копирование
и обновление существующих установок.

### Чистая Ubuntu 24.04 LTS

```bash
sudo bash install.sh --install
```

Скрипт не требует отдельного подтверждения. После загрузки и проверок начнётся
штатный установщик KIT. Он интерактивно предложит выбрать протоколы и другие
параметры. Для неинтерактивного запуска можно добавить `--yes` (совместимость) и аргументы
исходного KIT после `--`:

```bash
sudo bash install.sh --install --yes -- --protocols reality,hy2
```

Точные значения `--protocols` сверяйте с оригинальной инструкцией KIT.

### Если GitHub Releases и проверенные HTTPS-прокси недоступны

На другом компьютере скачайте официальный архив **строго** для `v3.9.0` и
архитектуры сервера (обычно AMD64):

https://github.com/MHSanaei/3x-ui/releases/tag/v3.9.0

Перенесите `x-ui-linux-amd64.tar.gz` на сервер (например, с помощью `scp`).
**Не распаковывайте и не заменяйте вручную** `/usr/local/x-ui`.

```bash
sudo bash install.sh --install --archive /root/x-ui-linux-amd64.tar.gz
```

Неверная SHA256 приведёт к отказу до каких-либо изменений. Для установки
на ARM64 нужен `x-ui-linux-arm64.tar.gz`.

Если GitHub Raw недоступен при подготовке скриптов, можно заранее поместить
в папку `/root/upstream` четыре исходных файла `3x-ui.sh`, `kit.sh`,
`kit-sub.py` из KIT `v1.2.1` и `install.sh` из панели `v3.9.0`
и передать `--upstream-dir /root/upstream`. Их контрольные суммы проверяются.
**Ограничение:** официальный установщик 3X-UI всё равно может обращаться к
GitHub Raw за собственным `x-ui.sh`; это не полностью автономная установка.

## Локальные тесты

```bash
python3 -m unittest discover -s tests -v
python3 -m compileall -q kit_custom
bash -n install.sh
```

Это **не является доказательством реальной работоспособности всех протоколов**:
для этого нужны интеграционные тесты на отдельном чистом VPS и клиентские
подключения через Prizrak-box. На работающем VPN-сервере тестировать установку
нельзя.

## Дорожная карта

1. **0.1.0** — безопасная загрузка 3X-UI v3.9.0, диагностика, защита готовой панели, загрузчик одной командой.
2. Выбор версии по матрице KIT / 3X-UI / Xray / форматы подписок / Prizrak-box.
3. `upgrade`, резервная копия SQLite+сертификатов и автоматический откат.
4. Русскоязычное TUI-меню, расширенная диагностика соединений и сертификатов.
5. Интеграционные тесты Ubuntu 24.04 и документация по эксплуатации.

## Ограничения и безопасность

- Патч применяется к **строго проверенным** версиям; если структура скрипта
  изменилась, установка прервётся до запуска установки.
- Используются официальные URL; сторонние зеркала по умолчанию не применяются.
- Существующие базы SQLite, учётные записи, сертификаты и настройки не правятся.
- Установка на пустой VPS всё ещё может изменять firewall, apt, nginx,
  systemd и сетевую конфигурацию, поскольку этим занимается исходный KIT.
- В первом этапе **нет** команды обновления работающей панели, восстановления
  или удаления. Нельзя применять официальный KIT `uninstall` вместо них.
- После публикации этого репозитория как приватного рекомендуется закрепить
  конкретный commit SHA, запускать скачанные скрипты только после просмотра
  и включить CI-проверки.
